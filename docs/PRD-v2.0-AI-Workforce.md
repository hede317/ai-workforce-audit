# HedeYou AI Workforce V2.0 — 完整产品需求与实施规范（存档压缩版）

> 本文件为 2026-10-31 用户下达的《HedeYou AI Workforce V2.0 完整产品需求、系统架构与开发实施规范》的规范性存档（章节完备、文字压缩）。
> 建设原则：Agent 驱动、任务目标导向、多 Agent 协作、自动执行、持续记忆、人工审批。第一期业务范围：培训、电商、留学、企业服务。核心目标：让一个人通过 AI 管理一支虚拟员工团队。

## 第一章 项目目标
传统固定工作流（定时采集→生成→发布）必须预先设计每一步、不能自主判断、不理解经营目标、缺长期记忆。本项目采用 AI Agent 架构：用户下达自然语言经营目标（如"推广巴基斯坦中企员工培训，一个月开发潜在客户"），系统自动完成理解→分析→计划→分派→搜集→生产→发布→开发→追踪→复盘→调整的闭环。

## 第二章 七层架构与 Agent 团队（12 员）
1. **AI Commander（指挥中心）**：自然语言入口、任务计划/分派/监控/汇报；文字指令，单次/长期/定时/并行任务，暂停/继续/取消。
2. **专业 Agent**（各自独立职责/记忆/工具权限/任务记录）：
   - 01 CEO（总经理）：目标拆解、资源分配、协调、质检、报告
   - 02 市场研究：竞品/趋势/需求/机会
   - 03 内容生产：选题/文章/SEO/翻译/脚本/文案/质检
   - 04 视频生产：脚本/数字人/语音/字幕/剪辑/封面（复用现有出片线，不重复开发）
   - 05 SEO/GEO：关键词/站检/结构化数据/GEO 优化/GSC 分析
   - 06 社媒运营：TikTok/YouTube/Meta/Instagram/LinkedIn；官方 API 或授权自动化，无授权走人工
   - 07 销售：潜客/分类/评分/跟进建议/CRM；未经审批不得发重要商业邮件或报价
   - 08 邮件营销：合法联系人/内容/分组/发送/退订管理
   - 09 电商运营：选品/竞品/描述/上架/订单/客诉；上架退款改价需审批
   - 10 培训与留学：课程/大纲/教材/学校/招生
   - 11 企业服务：ERP/AI 提效/诊断/方案
   - 12 数据分析：全渠道数据/转化/收入/Agent 效率/日报
3. Agent 标准配置：ID/角色/职责/系统提示词/模型/工具/工作记忆/知识库/权限/质检规则/最大执行时间/最大预算/错误处理/执行记录。
4. 协作规则：主从分派、并行执行、结构化传递、失败重分派、用户随时介入；禁止无限循环（最大层级/重试/时长/Token/工具次数）。
5. 任务状态：Created→Planning→Waiting Approval→Assigned→Running→Reviewing→Completed/Failed/Paused/Cancelled。

## 第三章 记忆（四类）+ Memory Manager
企业记忆（公司/业务/市场/价格/品牌）、用户记忆（习惯/偏好/审批规则，可查看修改删除）、任务记忆（做过什么/为什么/结果/教训）、专业知识库（文档/SOP/案例，全文+向量检索）。
更新机制：任务完成后 Memory Manager 判定去留；**未经用户确认的 Agent 推测不得直接写入企业知识库**。

## 第四章 工具中心 Tool Registry
所有工具统一登记（网页与研究/网站/内容/社媒/业务/数据六类），登记项含名称/参数/输出/认证/权限等级/超时/失败处理/调用日志；凭证服务端保管，Agent 不得读取原始密钥。

## 第五章 审批中心
自动执行：研究/整理/关键词/草稿/质检/分析/内部分配/日报。
**审批后执行**：对外发布、营销邮件、联系潜客、改价、创建广告、改预算、退款、对外报价、修改正式页面。
禁止：绕过授权、伪造客户资料、垃圾邮件、擅自资金交易、未批删数据、跨 Agent 泄露敏感信息。审批必须留痕（人/时间/内容/结果）。

## 第六章 经营业务管理中心（4 BU）
EDU 培训（learn）/ ECOM 电商（shop）/ STUDY 留学（study）/ ERP 企业服务（erp）。统一入总经理 Agent，各业务资料与客户数据按权限隔离。

## 第七章 全域营销系统
内容中心（选题→文章→脚本→视频→图片→多语言→发布→效果，关联 BU/IP/市场/活动）；数字人 IP 四席（企业数字化顾问/国际教育顾问/职场培训讲师/跨境商业观察）；生产流程=市场研究发现选题→Content 生成→Video 制作→SEO 检查→Social 平台版→**用户审批**→发布→Data 追踪→CEO 安排下一轮。SEO/GEO 支持 GSC/GA4/Sitemap/索引/关键词/结构化数据。广告：一期只备数据模型与连接接口，投放必须审批。

## 第八章 管理后台 13 区
总览 / AI Commander / Agent Center / Task Center / Memory Center / Tool Center / Content Center / Marketing Center / CRM Center / Business Center / Analytics Center / Approval Center / Settings。

## 第九章 技术选型
前端 Next.js+React+TS+Tailwind+shadcn；后端 Python FastAPI+PostgreSQL+SQLAlchemy+Alembic；Agent Runtime 独立服务、显式状态机（复杂多步可选 LangGraph）、统一 Tool Registry、业务逻辑不写死在提示词；n8n 保留为定时调度/确定性工作流/系统集成执行层（不再当智能决策中心）；数据 PG+Redis（按需）+S3+pgvector；模型经 Model Adapter 多供应商接入。
模块化单体优先，不一开始拆微服务。
调用链：用户指令→Commander→Planner→Orchestrator→Agent→Tool Registry→外部 API/n8n/网站→结果检查→Memory Manager→PG→报告。

## 第十章 安全与实施
认证/HTTPS/密钥加密/DB 不暴露公网/n8n 访问保护/备份/日志/有限重试/发布幂等/审批留痕/限流/防重复 Webhook/隐私合规。
按 P0 系统基础→P1 内容工厂→P2 分发→P3 闭环顺序实施；每阶段实际运行验收；禁止假数据冒充接口；未完成模块必须明确标注。
